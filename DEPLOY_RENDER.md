# Deploy GenAI Studio to Render

This package is based on your uploaded current project. It preserves the app, frontend, login/signup, and existing AI features, with minimal deployment changes.

## Before uploading to GitHub

- Do **not** upload `.env`, `data/chat_history.db`, or personal files in `data/uploads/`.
- This ZIP intentionally excludes those local secrets/data. Your original local project/database are not modified.
- Create a GitHub repository and upload these files, then create a Render Blueprint from the repository.

## Required Render environment variable

Set `GEMINI_API_KEY` to your own Gemini API key in Render's Environment settings. Never put it in source code or GitHub. `FLASK_SECRET_KEY` is generated by `render.yaml`.

## Persistent storage

The Render Blueprint requests a 1 GB persistent disk mounted at `/var/data`. The app stores its SQLite database and uploaded PDFs under `DATA_DIR`, so they persist across service restarts/deploys while the disk remains attached. The `starter` web-service plan and persistent disk are paid resources; review current Render pricing before confirming.

## Build/start and health check

Build: `pip install -r requirements.txt`

Start: `gunicorn --workers 1 --threads 4 --timeout 180 app:app`

Health check: `/health`

## Important limitations

- PDF semantic indexes are held in memory and are rebuilt when a PDF is uploaded; after a server restart, users may need to upload PDFs again before asking questions about them.
- This package does not migrate your local SQLite database into the online service. The online service starts with a new database unless you plan a separate migration.
- Test signup, login/logout, account isolation, chat persistence, memory isolation, PDF upload/Q&A, voice, Markdown, and exports on the live service before sharing it.
- Keep the local `.env`, database, and personal PDFs private.
